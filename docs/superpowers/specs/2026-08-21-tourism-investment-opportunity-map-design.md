# 부산 관광 숙박 투자기회 지도 설계

- 작성일: 2026-08-21
- 대상 서비스: `https://busanproduct.co.kr/tourism/`
- 주 사용자: 부산시 관광정책 담당자와 관광혁신TF 내부 사용자
- 상태: 구현 전 승인 설계

## 1. 목적

현재 지도는 구·군별 정책지원 순위를 500m 격자에 반복 표시하여, 사용자가 실제로
어느 생활권에 어떤 투자가 필요한지 판단하기 어렵다. 새 지도는 다음 질문에
근거 수치와 공간 패턴으로 답해야 한다.

1. 관광객과 교통 유입이 발생하지만 숙박 공급이 부족한 생활권은 어디인가?
2. 숙박시설은 충분하지만 노후·영세 시설이 밀집해 리모델링이 필요한 곳은 어디인가?
3. 신규 업체 진입이 정체되거나 폐업이 늘어나는 시장은 어디인가?
4. 관광지·교통거점과 숙박 공급이 공간적으로 연결되지 않는 곳은 어디인가?
5. 신규 숙박, 리모델링, 빈집 전환, 콘텐츠 투자 중 무엇을 먼저 검토해야 하는가?

대표 사용 시나리오는 구포역 반경 1km 생활권이다. 사용자는 구포역 주변의
숙박시설·객실·노후도·신규 및 폐업·철도와 대중교통 유입·관광객 수요·관광지 접근성을
한 화면에서 확인하고, `노후 숙박 리모델링 및 관광숙박 전환 우선 검토`와 같은
결론의 근거를 추적할 수 있어야 한다.

## 2. 분석 단위

지도는 세 가지 공간 단위를 함께 사용한다.

- 부산 전체와 권역: 서부산·동부산·기타 부산의 구조적 비교
- 생활권: 역·환승센터·주요 관광거점 중심 반경 1km
- 상세 격자: 부산 전역 500m 격자

구·군은 집계와 비교 단위로 유지하되, 구 전체를 같은 값으로 칠한 격자를 상세 분석으로
표현하지 않는다. 시설·관광지·교통거점은 실제 좌표를 사용한다.

## 3. 데이터 소스와 결합

### 3.1 숙박 공급

운영 DB의 현재 게시 run에 포함된 숙박 인허가 시설을 사용한다.

- 시설·객실 수와 시설당 객실 수
- 관광숙박업·외국인 수용 가능 업종 비중
- 도로명·지번 주소
- 인허가일, 폐업일과 영업 상태
- 건축물 사용승인 연도와 노후도

주소는 VWorld 지오코더로 좌표화한다. 결과는 주소 정규화 해시를 키로 캐시해 일일
파이프라인에서 반복 호출하지 않는다. 원문 주소와 상세 좌표는 내부 운영 DB에만 두고,
공개 지도 번들에는 정책상 허용된 필드만 투영한다.

### 3.2 공간 기반

VWorld 2D 지도 API를 배경지도로 사용한다. VWorld 데이터·WMS/WFS API로 다음 정보를
내부 분석에 결합한다.

- 행정경계와 500m 격자
- GIS 건물통합정보의 건물 경계
- 용도지역·지구와 토지이용 정보
- 주소 좌표화와 좌표 검증

VWorld 인증키는 Nginx 또는 전용 서버 API를 통해서만 사용한다. 정적 HTML, JavaScript,
Git, 로그, 공개 manifest에는 키를 넣지 않는다. API 장애 시 마지막 검증 캐시와 현재
게시 번들을 유지한다.

### 3.3 관광수요와 관광지

한국관광공사 관광데이터의 방문자 지표와 관련 관광지 코드·명칭을 사용한다. 관광지
좌표는 좌표를 제공하는 공식 관광 API 또는 VWorld 장소·주소 검색 결과로 보강하고,
소스와 기준일을 기록한다.

수요는 원천 단위를 유지한다. 방문자 수와 지수 값을 혼합하지 않으며, 금액이 아닌
소비지수는 원으로 표시하지 않는다. 체류시간 원천이 없는 동안 체류시간 항목은 화면에
표시하지 않는다.

### 3.4 교통수요

철도역·도시철도역·버스환승센터·공항·주요 도로 접근성을 위치 기반으로 계산한다.
승하차 또는 교통량 자료가 게시된 경우에만 이용량 지표를 표시한다. 현재 게시 fact가
0건이면 접근거리와 노선 연결만 제공하고, 이용량을 0으로 간주하지 않는다.

## 4. 핵심 지표

| 판단축 | 생활권·격자 지표 | 해석 |
|---|---|---|
| 공급량 | 시설 수, 확인 객실 수, 객실 밀도 | 절대적 숙박 공급 수준 |
| 밀집도 | 면적당 시설·객실, 최근접 시설 간 거리 | 숙박 상권 형성 정도 |
| 영세성 | 시설당 객실 중앙값, 20실 이하 비율 | 소규모 모텔 중심 구조 |
| 노후도 | 평균·중앙 건물연수, 20년·30년 이상 비율 | 리모델링 필요 가능성 |
| 관광숙박 역량 | 관광숙박 객실·시설 비중 | 관광객 수용에 적합한 공급 |
| 신규 진입 | 최근 5년 신규 인허가 수와 비율 | 민간 신규투자 활력 |
| 폐업 추세 | 연도별 폐업 수, 폐업률, 순증감 | 시장 쇠퇴·재편 위험 |
| 관광수요 | 방문자 수 또는 원천 지수 | 생활권 주변 관광수요 |
| 교통 접근 | 거점거리, 노선 수, 게시된 이용량 | 유입 가능성과 실제 유입 |
| 수요 대비 공급 | 방문수요/객실, 교통유입/객실 | 수요에 비해 객실이 부족한 정도 |

폐업률은 해당 기간 영업 가능 모집단을 분모로 계산할 수 있을 때만 표시한다. 현재
게시 데이터가 폐업을 수집하지 못한 경우 `0%` 대신 비표시하며, all-status 인허가
백필이 완료된 뒤 활성화한다.

## 5. 판정 모델

지도는 원천 지표와 정책 결론을 분리한다. 종합 결론은 다음 규칙을 근거와 함께 표시한다.

| 데이터 조합 | 1차 결론 |
|---|---|
| 높은 관광·교통수요 + 낮은 객실 공급 | 신규 숙박 공급 검토 |
| 높은 수요 + 노후 숙박 밀집 | 리모델링·관광숙박 전환 우선 |
| 높은 수요 + 영세시설 밀집 + 낮은 관광숙박 비중 | 공동 품질개선·브랜드화 검토 |
| 높은 접근성 + 낮은 관광수요 | 관광콘텐츠·동선 개선 선행 |
| 높은 수요 + 빈집 후보 + 제도상 가능 | 빈집 활용 숙박 전환 검토 |
| 낮은 수요 + 충분한 공급 | 신규 숙박 투자 신중 |

종합점수는 원천 지표를 숨기는 단일 블랙박스가 아니다. 화면에 구성 지표, 값, 기준기간,
권역 비교값, 데이터 커버리지를 함께 표시한다. 데이터가 부족하면 투자결론을 만들지 않고
`추가 데이터 확인 필요`로 표시한다.

## 6. 화면 구성

### 6.1 기본 화면

1. 상단: 서부산·동부산·기타 부산의 공급·노후·신규·폐업 비교
2. 좌측 지도: VWorld 2D 배경지도와 분석 레이어
3. 우측 판단 패널: 선택 생활권의 정책·투자 결론과 근거 지표
4. 하단: 생활권 순위표와 연도별 신규·폐업 추세

### 6.2 지도 레이어

기본 레이어는 `관광수요 대비 숙박공급 부족도`로 한다. 사용자는 다음 레이어를 바로
전환할 수 있다.

- 숙박시설 위치와 클러스터
- 객실·시설 밀집도
- 노후 숙박시설 밀집도
- 관광지와 방문수요
- 철도·도시철도·환승 거점과 접근성
- 신규 진입과 폐업 추세
- 민간투자 검토지역

첫 화면부터 구·군명, 핵심 생활권명, 범례와 색상 의미가 보여야 한다. 필터를 적용하지
않아도 부산 전체 패턴이 나타나야 한다.

### 6.3 클릭 상세

구포역 생활권을 선택하면 다음 형식으로 표시한다.

> 구포역 반경 1km는 교통 접근성과 방문수요가 높은 반면, 객실 공급과 관광숙박 비중이
> 비교 생활권보다 낮고 노후 소규모 숙박시설 비중이 높습니다. 신규 대형 공급보다 기존
> 모텔의 리모델링·관광숙박 전환을 우선 검토할 수 있습니다.

그 아래에 시설·객실·노후도·신규·폐업·방문수요·교통 근거와 서부산·동부산 비교값을
표시한다. AI 설명은 이 구조화된 근거만 해석하며 존재하지 않는 수치나 인과관계를
생성하지 않는다.

## 7. 데이터 파이프라인

1. 현재 게시 run의 숙박시설 주소를 결정한다.
2. 주소 정규화 및 해시 기반 VWorld 좌표 캐시를 조회한다.
3. 미좌표 주소만 제한 호출하고 부산 경계·구 일치 여부를 검증한다.
4. 관광지·교통거점 좌표를 공식 소스로 적재한다.
5. 시설·관광지·교통거점을 500m 격자와 1km 생활권에 공간 결합한다.
6. 공급·노후·시장변화·수요·접근 지표와 커버리지를 계산한다.
7. 품질 승인을 통과한 번들만 새 버전 디렉터리에 생성한다.
8. 운영 URL은 검증 완료 후 원자적으로 새 릴리스로 전환한다.

좌표화는 체크포인트와 재시도를 사용하며 부분 실패가 현재 게시 지도를 덮어쓰지 못하게
한다. 주소와 좌표가 바뀌지 않은 시설은 매일 재호출하지 않는다.

## 8. 품질과 검증

- 주소 보유 시설 수와 좌표 성공·실패·예외 수가 합계로 일치해야 한다.
- 좌표는 부산 경계 안에 있어야 하며 주소의 구와 공간 조인 구가 일치해야 한다.
- 동일 주소·시설의 중복 점은 병합 규칙과 근거를 가져야 한다.
- 500m 격자와 1km 생활권 집계가 원천 시설·객실 합계와 조정 가능해야 한다.
- 수요·교통 원천이 없으면 0으로 채우지 않는다.
- 각 정책 결론은 최소 수요·공급·품질 또는 접근성 근거와 커버리지를 가져야 한다.
- 이전 번들과 새 번들의 manifest·행 수·체크섬·현재 pointer를 검증한다.
- 기존 공공계약·지역상품·신용보증·민생100일 및 관광 URL의 HTTP 200을 배포 전후 확인한다.

## 9. 단계적 공개

1. 좌표화와 숙박 밀집·노후 레이어
2. 관광지·방문수요와 수요 대비 공급부족 레이어
3. 교통량 백필 후 교통 접근·유입 지표
4. 폐업 all-status 백필 후 폐업률·순증감
5. 빈집과 용도지역·건물정보 결합 후 전환 검토 레이어

각 단계는 데이터가 확보된 기능만 공개한다. 준비되지 않은 지표를 0이나 임의값으로
표현하지 않는다.
