## 2. 현재 완료 상태

### 빈집 건축물대장 연계

- 게시 개발후보: 총 23곳(A형 연속필지 4곳, B형 단독개발 예비후보 19곳)
- 건축물대장 연계 완료: 18곳
- 공식 API 조회결과 없음: 5곳
- 미조회: 0곳
- 전체 재평가 검토군 47필지를 건축물대장 수집 대상으로 사용한다. 게시후보만 조회하면 연계 후 순위가 바뀌면서 새 후보가 다시 미조회가 되는 문제가 발생하므로 수집 범위를 축소하면 안 된다.

5곳의 `조회 결과 없음`은 미조회가 아니다. 해당 PNU를 건축물대장 API 5종으로 조회했으나 행이 반환되지 않은 상태다. 건축물이 없다고 단정하지 말고 말소대장, 지번 변경, 부속건축물, PNU 불일치 여부를 원문대장으로 확인해야 한다.

### PNU 변환 규칙

- PNU 산 여부: `1=일반`, `2=산`
- 건축물대장 API 대지구분: `0=대지`, `1=산`
- 필수 변환: `PNU 1 -> API 0`, `PNU 2 -> API 1`

이 변환을 제거하면 일반 필지를 산 필지로 조회하여 대부분 0건이 되는 회귀가 발생한다.

## 6. 다음 우선 작업

1. 동 또는 필지 수준 방문수요를 후보 순위에 결합한다. 현재 자치구 방문수요를 개별 필지의 직접 수요로 해석하면 안 된다.
2. `조회 결과 없음` 5곳을 세움터·자치구 원문대장 또는 지번 변경 이력으로 보완한다.
3. 건축물대장 후보 보강 실행이 전체 파생 마트와 해시를 다시 계산해 약 35분 49초가 소요됐다. 후보 보강분만 증분 계산하도록 성능을 개선한다.
4. 지도 후보순위는 투자 확정순위가 아니다. 소유권, 접도·도로폭, 토지이용, 구조안전, 위반건축물, 소방·주차·위생, 사업비와 수익성을 별도로 검토한다.
5. 새 릴리스 발행 전에는 스테이징 디렉터리에서 매니페스트·요약·브라우저를 검증하고, 성공한 경우에만 공개 포인터를 원자적으로 전환한다.

## 7. 클라우드 작업 규칙

- 브랜치 `codex/busan-authority-filter`와 이 문서를 기준으로 시작한다.
- 공개 URL로 읽기 검증은 가능하지만, 서버 DB 갱신·재배포는 별도 서버 인증이 없는 클라우드 환경에서 완료했다고 주장하지 않는다.
- 비밀키나 인증파일을 코드, 로그, 채팅, GitHub에 복사하지 않는다.
- 데이터 수치 변경 시 공개 JSON, 화면 텍스트, 테스트 고정값, 매니페스트를 같은 릴리스에서 교차검증한다.
- `건축물대장 조회 결과 없음`을 `건축물 없음` 또는 `입지 부적합`으로 바꾸지 않는다.
